# Decisions

One line per decision made during the build: date, phase, decision, reason.

- 2026-11-25, kit: clean-room feature list from the public store listing only; no decompiling.
- 2026-11-25, kit: rounding half up on ms; equal-speed parts merge; tie between user stop and low storage = user.
- 2026-11-25, kit: no red-dot overlay; the foreground notification is the only recording indicator.
- 2026-11-25, kit: dark theme only for the MVP; new OOS Cam design system (Liquid Glass style).
- 2026-11-25, phase 0: gradle wrapper is created in T0.2 (check_env.sh requires gradlew); gate G0 is first fully green at T0.4, so T0.1-T0.3 are ticked on their own checks. Gates were not edited.
- 2026-11-25, phase 0: this cloud VM sets JAVA_TOOL_OPTIONS (sandbox proxy), so `java -version` prints a 'Picked up' line first and scripts/check_env.sh misreads the JDK; run it as `env -u JAVA_TOOL_OPTIONS -u _JAVA_OPTIONS scripts/check_env.sh`. The script was not edited.
- 2026-11-25, phase 0: compileSdk=targetSdk=36 (newest platform installed by setup_cloud.sh); compose-bom 2026.06.01 and core-ktx 1.18.0 are the newest versions tested that compile against 36 (2026.09.00 and core-ktx 1.19.1 were tried and need 37; 2026.08.00 and 1.19.0 were not tried).
- 2026-11-25, phase 0: spike code (SpikeActivity, spike service, spike math) is debug-only and throwaway; Phase 2 builds CaptureService fresh instead of growing it from the spike.
- 2026-11-25, phase 1: gate G1 cannot pass before T1.6 (runFixtures writes empty arrays until then); T1.1-T1.5 are ticked on their own tests plus `:core:test` and G0; acceptance counts are reported as progress only.
- 2026-11-25, phase 1: ambiguities in TEST_RULES settled by reading the oracle (read-only): per range E7 is checked before E4; E4 is checked before clipping (a range outside the trim window with a bad speed is E4, not W1); E3 is checked after clipping on kept ranges only; warnings are emitted together with errors; exportHeight, W2 and audio are computed even when errors exist; equal-speed neighbours merge before rounding; E5 is computed only when E3, E4, E6 and E7 are absent.
- 2026-11-25, phase 1: a recording with no `stopAtMs` and no low-storage sample has no end; planSegments throws IllegalArgumentException (the rules do not define a result).
- 2026-11-25, phase 1: planSegments takes the low-storage sample with the smallest tMs (the oracle takes the first in list order; they agree on sorted input) and rejects negative stopAtMs and non-positive segmentMinutes with IllegalArgumentException; both are deliberate readings the rules leave open.
- 2026-11-25, phase 2: core StopReason gains error, thermal, permission_revoked, phone_call (SPEC stopReason list); planSegments still returns only user or low_storage; existing serial names unchanged.
- 2026-11-25, phase 2: CaptureService reads its engine and clock from the CaptureDeps holder so Robolectric tests can swap them (Robolectric builds the service itself).
- 2026-11-25, phase 2: capture does not reimplement segment rules; the cap, file name and low-storage threshold come from public :core helpers that planSegments itself uses, so G1 acceptance guards them. Segments roll on recorded duration (CameraX Status events), not wall time.
- 2026-11-25, phase 2: READ_PHONE_STATE is not declared (not in the SPEC permissions matrix), so the TelephonyCallback path is skipped at runtime; phone calls are detected with AudioManager.OnModeChangedListener (MODE_IN_CALL, MODE_IN_COMMUNICATION, MODE_CALL_SCREENING), which needs no permission. Ringing alone does not stop recording.
- 2026-11-25, phase 2: free space uses decimal MB (1 MB = 1,000,000 bytes), the same unit as the 3,900 MB SD cap in :core.
- 2026-11-25, phase 2: segments are written through FileDescriptorOutputOptions for both MediaStore (own insert with IS_PENDING=1) and SAF, so the segment URI is known before recording starts; after finalize IS_PENDING is cleared even for a failed segment so Phase 3 can list it as Damaged.
- 2026-11-25, phase 2: Room v1 has only recording_session and segment; session id is a UUID string so writes can be queued without waiting for a generated key; the segment index column is segment_index (index is an SQL keyword). Width/height store the planned frame size of the quality preset, not the size CameraX fell back to.
- 2026-11-25, phase 2: app/schemas is added to the debug assets because Robolectric reads the merged debug assets, not unit-test assets; release builds do not carry the schema files.
- 2026-11-25, phase 3: gate G3 cannot pass before T3.6 (app/build/acceptance/X01_plan.json is written by AcceptanceUseCaseTest); T3.1-T3.5 are ticked on their own tests, the full testDebugUnitTest and `scripts/check.sh 2`.
- 2026-11-25, phase 3: a library file is Damaged when its top-level boxes hold no complete moov box (SPEC data rule 5); the probe reads only box headers. Deleting a file removes its segment row, and a finished session with no segment left; a session still recording is never removed.
- 2026-11-25, phase 3: READ_MEDIA_VIDEO is not declared. androidx PickMultipleVisualMedia itself falls back to ACTION_OPEN_DOCUMENT when the system photo picker is unavailable, and neither path needs a storage permission, so the SPEC fallback permission is never needed.
- 2026-11-25, phase 3: the export Composition is built only from the ExportPlan that :core returned; the source URI is looked up by clip order from the same project because PlanPart has no URI field, and adding one would change the JSON that acceptance compares exactly. A test gives the mapper a plan that differs from the project and checks the Composition follows the plan.
- 2026-11-25, phase 3: part speed uses EditedMediaItem.setSpeed(SpeedProvider) (Media3 1.11.1), which changes audio and video together, instead of a video-only SpeedChangeEffect. With audio on, the sequence declares the audio track type so clips without a mic track get silence (experimentalSetForceAudioTrack is not allowed with explicit track types).
- 2026-11-25, phase 3: Room v2 uses AutoMigration(1, 2) because the change only adds tables; Room generates the SQL from the exported schemas, and MigrationTestHelper validates v2 against 2.json. Column clip_order replaces order (SQL keyword); speed is TEXT so 1.5 stays exact. Project names default to the save time until renaming exists (Phase 4 UI).
